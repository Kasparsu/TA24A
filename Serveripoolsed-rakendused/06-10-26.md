## 🗂️ Topics Covered

> 🗃️ Last time the posts moved into the database and got their own `Post` and `User`
> classes, but every query still went through `new DB()` with the table and class
> written out by hand. This session gave the models a shared parent that knows its own
> table, then started the admin side: a table of all posts and a form that saves a new one.

### 1. 🧬 An abstract `Model` class

`Post` and `User` both need the same things: an `id`, a table name, and the code that
fetches rows into objects. That shared part went into a parent class:

```php
namespace App\Models;

use App\DB;

abstract class Model {
    public $id;
    public static $table;

    public static function all(){
        $db = new DB();
        return $db->all(static::$table, static::class);
    }
}
```

- **`abstract`** says this class is only there to be inherited from. A plain `Model` has
  no table and means nothing on its own, so `new Model()` should never happen, and with
  `abstract` PHP refuses it.
- **`public static $table`** declares that every model has a table name. The parent leaves
  it empty; each child fills it in.
- **`$id`** moved up here, because every table has one.

The children only say what is different about them:

```php
class Post extends Model {
    public static $table = 'posts';

    public $title;
    public $body;
    public $author;
```

`User` is the same with `$table = 'users'`.

![Abstract](https://api.memegen.link/images/soup-nazi/new_Model()/No_object_for_you!_It_is_abstract.png)

### 2. 🎯 `static::` and shorter queries

Inside `all()`, `static::$table` and `static::class` mean *the class the method was
called on*, not the class where the method is written. So `Post::all()` reads
`Post::$table` (`'posts'`) and fills `Post` objects, and `User::all()` does the same for
users. (`self::` would always point at `Model`, whose table is empty.)

The controller no longer needs to know about `DB`, table names or class names:

```php
// before
$db = new DB();
$posts = $db->all('posts', Post::class);

// after
$posts = Post::all();
```

Side note from the lesson: if the connection fails with a missing driver error on Linux,
PHP's MySQL driver for PDO usually has to be installed as a separate package. Which one
depends on your distribution's package manager.

### 3. 🔎 `where()`: World posts and U.S. posts

The front page should not show *all* posts, only the ones in its category. `DB` got a
second query:

```php
public function where($table, $class, $field, $value) {
    $sql = "SELECT * FROM $table WHERE $field='$value'";
    $result = $this->conn->query($sql);
    $result->setFetchMode(PDO::FETCH_CLASS, $class);
    return $result->fetchAll();
}
```

and `Model` a static `where($field, $value)` that passes it on, just like `all()`. The
hard-coded post arrays in `PublicController` disappeared:

```php
$posts = Post::where('category', 'world');
// ...
$posts = Post::where('category', 'us');
```

The posts were now objects, not arrays, so the posts partial had to switch from
`$post['title']` to `$post->title` (and `date` became the table's `created_at`). If you
have a Technology page, it gets a `Post::where('category', 'tech')` the same way.

> Heads-up: the value goes straight into the SQL text. That is fine while the only values
> are fixed strings in our own code, but never let a user's input in there like this.

### 4. 🛠️ An admin controller

The admin side gets its own controller, so `PublicController` stays about the public
pages:

```php
Route::get('/admin/posts', [PostsController::class, 'index']);
```

```php
class PostsController
{
    public function index()
    {
        $title = 'Posts';
        $posts = Post::all();
        view('posts/index', compact('title', 'posts'));
    }
```

`view('posts/index')` works because `view()` only glues the name into a path: the admin
views live in their own `views/posts/` folder. One folder deeper means the partial
includes need one more step back: `__DIR__ . '/../partials/header.php'`. The unused
Culture link in the nav became Posts.

### 5. 🧭 Why links start with `/`

The new page loaded without any styles. The browser's Network tab showed why: it asked
for `/admin/blog.css`. The header had `href="blog.css"`, a **relative** path, and the
browser resolves it against the folder it thinks it is in. `/admin/posts` is not a real
folder, but to the browser it looks like one.

```html
<link href="/blog.css" rel="stylesheet" />
```

With the leading `/` the path starts from the site root, wherever the page is. That is
why every link in this project has had a `/` in front: relative paths are shorter to
write, but the first time you add a "folder" to an address, they break.

### 6. 📋 A Bootstrap table with action buttons

An admin view does not need to be pretty, it needs to be readable, so the posts went into
a table. Bootstrap styles plain HTML tables with a few classes:

- **`table`**: the base style
- **`table-striped`**: alternating row colours
- **`table-hover`**: highlights the row under the mouse

A table has up to three parts: **`<thead>`** for the header row (`<th>` cells, bold by
default), **`<tbody>`** for the data, and an optional **`<tfoot>`**, which repeats the
headings at the bottom of a long table. One row per post:

```php
<?php foreach (($posts ?? []) as $post): ?>
    <tr>
        <td><?= $post->id ?></td>
        <td><?= $post->title ?></td>
        <td><?= $post->author ?></td>
        <!-- category, created_at, updated_at -->
        <td>
            <div class="btn-group">
                <a href="#" class="btn btn-info">View</a>
                <a href="#" class="btn btn-warning">Edit</a>
                <a href="#" class="btn btn-danger">Delete</a>
            </div>
        </td>
    </tr>
<?php endforeach ?>
```

The body is left out of the table on purpose: it can be very long. **View** will show
the full post, **Edit** change it, **Delete** remove it (all still `#` for now). The
**button group** (<https://getbootstrap.com/docs/5.3/components/button-group/>) sticks
them together, and the colours carry meaning: viewing is harmless (`info`), editing needs
some care (`warning`), deleting is dangerous (`danger`). Same-coloured buttons side by
side are how people click the wrong one.

A **New Post** button went above the table, linking to `/admin/posts/create`.

![Button colours](https://api.memegen.link/images/regret/Clicked_the_blue_Delete_button/I_immediately_regret_this_decision.png)

### 7. 📝 The create form

```php
Route::get('/admin/posts/create', [PostsController::class, 'create']);
```

`create()` only shows a view, no data needed. The form started from Bootstrap's form
control example (<https://getbootstrap.com/docs/5.3/forms/form-control/#example>), then
got tuned: an input for the title, a `<textarea>` for the body, plain text inputs for
category and author (category could become a `<select>` later):

```html
<form action="/admin/posts" method="POST">
    <div class="mb-3">
        <label for="title" class="form-label">Title</label>
        <input name="title" type="text" class="form-control" id="title" placeholder="Post title">
    </div>
    <div class="mb-3">
        <label for="body" class="form-label">Content</label>
        <textarea name="body" class="form-control" id="body" rows="3"></textarea>
    </div>
```

Two details:

- **The label is for people, the `name` is for us.** "body" means something to a
  developer and nothing to the person filling in the form, so the label says *Content*
  while the field keeps `name="body"`.
- **The first submit came back empty.** The copied example had no `name` attributes, and
  a field without a `name` is not sent. Bootstrap's (and every other framework's) examples
  never include them, so add them yourself every time you copy one.

![No name](https://api.memegen.link/images/seagull/Copied_the_Bootstrap_form/NO_NAME_ATTRIBUTES.png)

### 8. 🔁 Same address, different method

The form posts to `/admin/posts`, an address that already shows the list. That is not a
conflict, because the router now matches the method too:

```php
Route::get('/admin/posts', [PostsController::class, 'index']);
Route::post('/admin/posts', [PostsController::class, 'store']);
```

GET `/admin/posts` lists the posts, POST `/admin/posts` stores a new one. This pairing
(`index`, `create`, `store`) is the usual naming you will meet in frameworks too.

While testing: after changing the form, going **Back** and submitting again may still
send the old form. Back does not ask the server for the page again; the browser shows the
copy it already has. **Refresh** after a change.

### 9. 💾 `save()`: from object to `INSERT`

The goal was for the controller to read like this:

```php
public function store() {
    $post = new Post();
    $post->title = $_POST['title'];
    $post->body = $_POST['body'];
    $post->category = $_POST['category'];
    $post->author = $_POST['author'];
    $post->save();
    redirect('/admin/posts');
}
```

`save()` goes into `Model`, so users get it too. Unlike `all()` and `where()` it is **not
static**: it saves *this* object. `get_object_vars($this)` turns the object's properties
into a `name => value` array; the columns the database fills in itself are removed:

```php
public function save(){
    $db = new DB();
    $fields = get_object_vars($this);
    unset($fields['id']);
    unset($fields['created_at']);
    unset($fields['updated_at']);
    $db->insert(static::$table, $fields);
}
```

`DB::insert` builds the SQL from that array: the keys become the column list, the values
the `VALUES` list, both joined with `implode`:

```php
public function insert($table, $fields){
    $fieldNames = array_keys($fields);
    $fieldNamesText = implode(', ', $fieldNames);
    $fieldValuesText = implode("', '", $fields);
    $sql = "INSERT INTO $table ($fieldNamesText) VALUES ('$fieldValuesText')";
    $this->conn->exec($sql);
}
```

> Heads-up: same story as `where()`. This time the values *are* user input, so a title
> with an apostrophe in it breaks the query. Keep it in mind until the queries get safer.

![get_object_vars](https://api.memegen.link/images/oprah/You_get_a_column/Every_public_property_gets_a_column.png)

### 10. 🧰 Two more helpers

```php
function dd(...$values) {
    dump(...$values);
    die;
}

function redirect($path) {
    header("Location: $path");
}
```

- **`dd()`** (dump and die) prints and stops the script, handy for checking what `$_POST`
  holds before anything else runs.
- **`redirect()`** sends a `Location` header, so after storing, the browser goes back to
  the list with a fresh GET. Refreshing the list then does not submit the form again.

## ✅ Takeaways

1. **An abstract `Model` holds what all models share**; children only set `$table` and
   their own fields.
2. **`static::` means the class the method was called on**, so `Post::all()` and
   `User::all()` share one method.
3. **Admin pages get their own controller and view folder**; include paths go one step
   further back.
4. **Start links with `/`.** Relative paths break as soon as an address looks like a folder.
5. **Copied form examples have no `name` attributes.** Add them, or nothing is sent.
6. **One address can serve GET and POST**: `index` lists, `store` saves, `create` shows the form.
7. **`save()` turns an object into an `INSERT`** with `get_object_vars`, then `redirect()`
   sends the browser back to the list.
