### 2. 📦 Namespaces

```php
namespace App;

class Router { ... }
```

A namespace is a surname for classes. `App\Router` and some library's `Router` can now
coexist, and the name tells you where the class lives: `App\Controllers\PublicController`
sits in `src/Controllers/PublicController.php`.

To use a class from elsewhere:

```php
use App\Router;
```

### 3. 🤖 Autoloading

Without it, every class needs its own `require_once` before use, and forgetting one is a
fatal error. With it, PHP asks *you* how to find a class the first time it is used:

```php
spl_autoload_register(function ($class) {
    $class = substr($class, strlen('App\\'));   // App\Router -> Router
    $class = str_replace('\\', '/', $class);    // Controllers\X -> Controllers/X
    require_once __DIR__ . "/../src/$class.php";
});
```

The rule this implements (*namespace mirrors folder*) is the same convention Composer's
PSR-4 autoloader uses. Once you meet Composer, this function disappears, but it does
exactly this.

### 4. 🚦 A `Router` and a `Route`

The `switch` became two small classes. A `Route` is just a path and what to do:

```php
class Route {
    public function __construct(private string $path, private $action) {}
    public function getPath()   { return $this->path; }
    public function getAction() { return $this->action; }
}
```

The `Router` keeps a list of them and finds the one that matches:

```php
class Router {
    /** @var Route[] $routes */
    private static $routes = [];

    public static function addRoute(string $path, callable $action) {
        self::$routes[] = new Route($path, $action);
    }

    public function match(): Route | false {
        foreach (self::$routes as $route) {
            if ($route->getPath() === $this->path) {
                return $route;
            }
        }
        return false;
    }
}
```

Two type details worth noticing:

- **`Route | false`** is a *union type*: the method returns a `Route`, or `false` when
  nothing matched, and the signature says so.
- **`/** @var Route[] */`** is a docblock type. PHP itself cannot say "array of Route",
  but your editor reads the comment and autocompletes `$route->getPath()` accordingly.
  Types reference: <https://docs.phpdoc.org/guide/guides/types.html#supported-types>

![Router](https://api.memegen.link/images/captain/Look_at_me/I_am_the_router_now.png)

### 5. 🗺️ Routes in their own file

```php
// routes.php
Router::addRoute('/us', function () {
    $title = 'U.S';
    $posts = [ ... ];
    include __DIR__ . '/views/us.php';
});
```

Each route's action is a **closure**: an anonymous function stored and called later. And
`public/index.php` shrinks to setup plus three lines of dispatch:

```php
$router = new Router($_SERVER['REQUEST_URI']);
$match  = $router->match();
if ($match) {
    call_user_func($match->getAction());
} else {
    echo 404;
}
```

Adding a page no longer means editing the entry point; it means adding one `addRoute`
call. That is the whole reason routers exist.

## ✅ Takeaways

1. **Namespaces are surnames for classes**, and they mirror the folder structure.
2. **`spl_autoload_register`** replaces a `require` per class, the same rule Composer uses.
3. **A route is a path plus an action.** The router just finds the matching one.
4. **Union types and docblock types** let the editor know what you mean.
5. **New page = one `addRoute` call.** The entry point stays untouched.
