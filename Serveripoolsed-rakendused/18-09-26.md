### 1. 🔌 Interfaces

```php
interface Logger {
    public function log($message);
}
```

An interface is a **contract** — no bodies, only the shape. Any class that says
`implements Logger` must provide a `log($message)` method.

```php
class ConsoleLogger implements Logger {
    public function log($message) {
        echo "$message\n";
    }
}

class NothingLogger implements Logger {
    public function log($message) {
        // deliberately does nothing
    }
}

class FileLogger implements Logger {
    public function log($message) {
        $file = fopen('log.txt', 'a');
        fwrite($file, "$message\n");
        fclose($file);
    }
}
```

**Why it's worth the ceremony** — look at what consumes it:

```php
// library
class Task {
    public function job(Logger $logger) {
        for ($i = 0; $i < 10; $i++) {
            // do some work
            $logger->log("Job $i was done!");
        }
    }
}

// user code
$logger = new FileLogger();
$task = new Task();
$task->job($logger);
```

`Task::job()` type-hints **`Logger`**, not any specific class. It has no idea whether logging
goes to the console, to a file, or nowhere at all — and doesn't need to.

> 🧠 Note the `// library` / `// user code` split in the example. `Task` and the interface are
> the library; `FileLogger` was written afterwards by someone else. It plugs straight in
> because both sides agreed on the interface. **That is the entire point.**

**On `fopen`/`fwrite`/`fclose`:** open the file (`'a'` = append, don't overwrite), write, close.
Forgetting to close leaves the handle open.

A second empty `interface Writer {}` was sketched alongside — a class can implement more than
one interface, unlike `extends`, which allows only one parent.

### 2. 🖼️ PHP Inside HTML

A `.php` file is **HTML with escapes into PHP**. Anything outside `<?php … ?>` is sent to the
browser untouched.

```php
<?php
$name = 'Kaspar';
?>

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
</head>
<body>
    <h1>Hello <?=$name?>!</h1>

    <ul>
        <?php for($i=0;$i<10;$i++): ?>
            <?php if($i%2 === 0): ?>
                <li style="color:green"><?= $i ?></li>
            <?php else: ?>
                <li style="color:red"><?= $i ?></li>
            <?php endif ?>
        <?php endfor ?>
    </ul>
</body>
</html>
```

**Two new pieces of syntax:**

| Syntax | Meaning |
|---|---|
| `<?=$name?>` | Short echo — shorthand for `<?php echo $name; ?>` |
| `for(…):` … `endfor` | **Alternative syntax** — colon instead of `{`, `endfor`/`endif`/`endforeach` instead of `}` |

**Why the alternative syntax:** with HTML in between, a stray `}` is impossible to match by
eye. `<?php endfor ?>` says exactly what ended. The logic is unchanged — only the punctuation.

The example combines both: a loop with a conditional inside it, colouring even numbers green
and odd numbers red. Note `$i % 2 === 0` — the even test from the operators lesson, now doing
something visible.

**Serving it**, saved into `server.sh` so nobody has to remember it:
```bash
php -S localhost:8000
```

### 3. 🅱️ The Bootstrap Blog Template

Rather than writing a site's CSS from scratch, a ready-made **Bootstrap** example is used.

> 💼 The reasoning: on the back end, the markup usually arrives from someone else — a designer
> or a front-end developer. The skill that matters is **reading markup you didn't write** and
> turning it into a working template.

| Link | What it is |
|---|---|
| <https://getbootstrap.com/docs/5.3/getting-started/introduction/> | Bootstrap — getting started |
| <https://getbootstrap.com/docs/5.3/examples/> | Ready-made example pages |

The downloaded blog example arrives as one long `index.php` plus `assets/` and `blog.css`. It
was immediately **split into partials**:

```
partials/
  header.php        <head>, meta, stylesheets
  nav.php           navigation
  theme-select.php  light/dark switcher
  icons.php         inline SVG icons
  hero.php          banner
  featured.php      featured post
  posts.php         the post list
  sidebar.php       side column
  footer.php
```

leaving `index.php` as an assembly file:

```php
<?php include __DIR__ . '/partials/header.php'; ?>
  <main class="container">
    <?php include __DIR__ . '/partials/hero.php'; ?>
    <?php include __DIR__ . '/partials/featured.php'; ?>

    <div class="row g-5">
      <div class="col-md-8">
        <?php include __DIR__ . '/partials/posts.php'; ?>
      </div>
      <div class="col-md-4">
        <?php include __DIR__ . '/partials/sidebar.php'; ?>
      </div>
    </div>
  </main>
<?php include __DIR__ . '/partials/footer.php'; ?>
```

**`__DIR__`** is the directory of the current file, so includes resolve no matter where the
server was started from.

**Why split it:**

| Benefit | Why |
|---|---|
| Findable | "The nav is broken" → open `nav.php` |
| Reusable | The same header and footer serve every page |
| One place to change | Edit the nav once; every page updates |

> 🧠 Same instinct as putting repeated code in a function: say it once, and keep each piece
> small enough to hold in your head.

## ✅ Takeaways

1. **An interface is a contract.** Type-hint the interface and implementations become
   swappable — including ones you haven't written yet.
2. **`fopen`/`fwrite`/`fclose`** — `'a'` appends; always close.
3. **A `.php` file is HTML with holes in it.** `<?= ?>` prints; `if: … endif` keeps it readable.
4. **`__DIR__`** makes includes independent of the working directory.
5. **Split long templates into partials.** One file per section.
6. **Reading someone else's markup is the real back-end skill.**
