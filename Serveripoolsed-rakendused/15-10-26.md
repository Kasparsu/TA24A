### 1. 🧂 Fixing the salt at login

The extra salt from last time glued the name, email and password together, but the login
form has no name field. `$_POST['name']` was empty at login, so the string never matched the
one built at registration. The name has to come from the user found in the database:

```php
if(!$user || !password_verify($user->name . $_POST['email'] . $_POST['password'] . md5('yolo'), $user->password)) {
    return redirect('/login');
}
```

Testing the login at the end of last lesson would have caught it.

### 2. 🖼️ A file field on the form

The post form got an image field:

```php
<div class="mb-3">
    <label for="image" class="form-label">Image</label>
    <input name="image" type="file" class="form-control" id="image" >
</div>
```

Submitting it and dumping `$_POST` and `$_FILES` showed the problem: `$_POST['image']` held
only the **file name** as text, and `$_FILES` was **empty**. A form sends text by default.
How it is encoded is set by the form's `enctype` attribute, which has three values:

- `application/x-www-form-urlencoded`: the default, fields as `name=value` pairs.
- `text/plain`: plain text, rarely useful.
- `multipart/form-data`: the body is sent in several parts, so binary files fit in. This is
  the one for uploads.

```php
<form action="/admin/posts" method="POST" enctype="multipart/form-data">
```

It is one of those things nobody remembers, and without it you scratch your head for a
long time. After a refresh the text fields still arrive in `$_POST`, and the image shows up
in `$_FILES['image']` as an array: the original `name`, a guessed `type` (from the
extension), `tmp_name`, an `error` code and the `size` in bytes.

![enctype](https://api.memegen.link/images/harold/The_form_sends_the_image/But_$__FILES_is_empty_(forgot_enctype).png)

### 3. 📂 Keeping the file: `move_uploaded_file`

`tmp_name` points to a temporary folder, but looking there afterwards finds nothing. PHP
keeps the upload **only until the request ends**, and deletes it unless the code does
something with it. Otherwise anyone could write a script that sends a million files a
second until the server's disk is full.

To keep a file, move it somewhere permanent with `move_uploaded_file($from, $to)`. The
target is a new `public/uploads/` folder. The folder should be in git, its contents should
not, and git does not track empty folders. Instead of a `.gitkeep` placeholder, the folder
gets its own `.gitignore` that ignores everything except itself:

```
*
!.gitignore
```

### 4. 🎲 Never keep the original file name

Saving under the uploaded name is dangerous. Names can be crafted to do nasty things, and
even innocent names collide: every camera calls its photos `IMG_0001.jpg` and so on. The
lesson told the story of an early "private" photo gallery that stored uploads under their
original names, so a later upload with the same name silently replaced someone else's
family photo. Keep the original name in the database if you need it (for example to hand
it back on download), but store the file under a generated name.

Only the **extension** is worth keeping. MD5 is fine here (it is not a password), but the
MD5 of the name alone would repeat for the same name, so `microtime()` and a random
integer between `PHP_INT_MIN` and `PHP_INT_MAX` go in too. And since even that is not
strictly guaranteed to be unique, a `do ... while` loop tries again while the name is taken:

```php
public function store() {
    $tmp = $_FILES['image']['tmp_name'];
    $ext = pathinfo($_FILES['image']['name'], PATHINFO_EXTENSION);
    $uploadDir = __DIR__ . '/../../public/uploads/';

    do {
        $filename = md5($_FILES['image']['name'] . microtime() . rand(PHP_INT_MIN, PHP_INT_MAX)) . ".$ext";
    } while(file_exists($uploadDir . $filename));

    move_uploaded_file($tmp, $uploadDir . $filename);
```

Uploading the very same picture several times now gives a new file every time. The file
name is not saved with the post yet; that part was left for later.

### 5. 🎼 Composer

So far every line of the project was written by hand, which is great for learning and a
bad idea for production. In real projects nobody writes their own router, autoloader or
database layer. PHP's package manager is **Composer** (like npm for JavaScript, with cousins
in most languages: pip, cargo and so on). Installing it:

- **Windows:** the installer from getcomposer.org. On the school computers choose the
  install for the current user only, and check that it picks up the right PHP.
- **Linux/macOS:** the command line instructions, then move `composer.phar` to
  `/usr/local/bin/composer` so it is on the path.

Open a new terminal and `composer --version` should answer. Composer is a global tool, it
does not go into the project.

`composer init` turns the project into a Composer project and asks a series of questions.
The package name (usually `vendor/project`), description, author (taken from the git
config), minimum stability, type `project` and a license can all be accepted or filled in
as you like (the license is just a text; you could even write your own). It also asks for
dependencies, which we skip for now, and offers a PSR-4 autoload mapping: it suggests a
namespace based on the package name, but ours has always been `App`, so `composer.json`
was edited afterwards:

```json
"autoload": {
    "psr-4": {
        "App\\": "src/"
    }
},
```

After changing the mapping, the generated files in `vendor/` have to be rebuilt:
`composer dump-autoload`. The `vendor/` folder is Composer's `node_modules`: not our code,
always reproducible, so it goes into `.gitignore`:

```
/vendor/
```

### 6. 📏 PSR: the standards we have been following

**PSR** stands for PHP Standard Recommendation: rules everybody agrees on, so code from
different people and projects looks the same and fits together.

- **PSR-1**, basic coding standard (<https://www.php-fig.org/psr/psr-1/>): this is why
  class names are `StudlyCaps`, methods `camelCase` and constants upper case. The lessons
  have quietly followed it all along.
- **PSR-12**, extended coding style (<https://www.php-fig.org/psr/psr-12/>): braces,
  spacing and the rest of the layout details. PHP itself does not care, but open source
  projects and companies expect it.
- **PSR-4**, autoloading (<https://www.php-fig.org/psr/psr-4/>): how a namespace and class
  name map to a folder and file. The autoloader written in class already worked exactly
  this way, which is why Composer's PSR-4 loader is a drop-in replacement.

So the home made `spl_autoload_register` in `public/index.php` went, and one line took its
place:

```php
require __DIR__ . '/../vendor/autoload.php';
```

The site kept working as before.

### 7. 🔍 Packagist and `symfony/var-dumper`

Packages are found on **Packagist** (<https://packagist.org/>). A quick search showed
there is a package for everything built so far: routers (most of them far more capable than
ours), ORMs and query builders for the database, image processing, Excel, PDF generation.

Rather than replace something big, the lesson took a small one: the `dump()` and `dd()`
helpers we use all the time. **symfony/var-dumper**
(<https://packagist.org/packages/symfony/var-dumper>) provides both, only better:

```
composer require symfony/var-dumper
```

```json
"require": {
    "symfony/var-dumper": "^8.1"
}
```

Composer downloaded it along with what it depends on. Running it as is would clash,
because the package defines `dump()` and `dd()` and `helpers.php` already had functions with
those names, so ours were deleted. A `dump($posts)` in `PublicController` showed the result:
coloured, collapsible output that also marks each property as public, protected or private.

Symfony is a framework built out of separate packages, and each of them can be used on its
own; several other frameworks are partly made of Symfony components.

![var-dumper](https://api.memegen.link/images/panik-kalm-panik/composer_require_symfony~svar--dumper/It_gives_us_dump()_and_dd()/We_already_have_a_dump()_in_helpers.php.png)

### 8. 🔒 `composer.lock` and supply chain worries

A student asked what happens if a package gets taken over and a malicious version is
published. That is a real risk (supply chain attacks, where a backdoor is slipped into a
widely used library). Some protection: `composer require` added a **`composer.lock`** file
(like `package-lock.json`) that pins the exact versions installed, so a later install does
not silently pick up a new release. Small, little known packages are the riskier ones; a
big project like Symfony has many eyes on it.

### 9. 🚑 "Failed opening vendor/autoload.php"

Remember this error: a `require` of `vendor/autoload.php` that fails. It almost always means
the project was freshly cloned from GitHub and `vendor/` does not exist, because it is not in
git. Fix:

```
composer install
```

which installs exactly what `composer.lock` lists. The commands to remember:

- `composer require <package>`: add a new package.
- `composer install`: install what the project already needs (after a clone).
- `composer update`: move to newer versions allowed by `composer.json`.

## ✅ Takeaways

1. **Build the salted string from the same data at login as at registration**: take the
   name from the user in the database, not from a form that has no name field.
2. **File uploads need `enctype="multipart/form-data"`**; the file then arrives in
   `$_FILES`, not `$_POST`.
3. **Uploads are temporary.** Move them with `move_uploaded_file` or they are deleted when
   the request ends.
4. **Never store a file under its original name.** Keep the extension, generate a random
   name and loop until it is free.
5. **A folder's own `.gitignore` with `*` and `!.gitignore`** keeps the folder in git and its
   contents out.
6. **Composer is PHP's package manager**: `composer init`, a PSR-4 autoload entry,
   `vendor/autoload.php`, and `vendor/` in `.gitignore`.
7. **PSR-1, PSR-12 and PSR-4** are the shared rules for naming, layout and autoloading.
8. **Find packages on Packagist** before writing your own; `symfony/var-dumper` replaced our
   `dump()` and `dd()`.
9. **`composer.lock` pins exact versions.** After a fresh clone, "Failed opening
   vendor/autoload.php" means: run `composer install`.
