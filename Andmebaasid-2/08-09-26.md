### 1. 🔧 Repository Setup

The usual start-of-course routine, done on the classroom machines:

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```

**Once per machine**, not per project, and not a login. Use the address your GitHub account
knows about so commits get attributed to you.

Then: create a working directory, create a **public** repository on GitHub, make a first
commit, and push. GitHub asks you to sign in the first time.

### 2. 🗃️ Where This Course Starts From

Databases 1 is assumed: you've written SQL, built tables, and most of you have done something
with a database at work or on a project. The fundamentals aren't being re-taught.

**What this course is about instead:** the database *technologies*: that there is more than
one, that they behave differently, and that choosing between them is a real decision.

> 🤖 On AI: for ordinary SQL the free assistants are genuinely good now, and you should expect
> to use them. That's part of why the course spends its time on the surrounding technology
> rather than on drilling query syntax.

Fair warning given openly: nobody knows every one of these systems in depth, including the
instructor: expect to do some of your own reading.

---

### 3. 🐳 Why Docker Comes First

To try several database systems you'd normally install several database servers, each with its
own service, its own config, and its own mess left behind afterwards.

**Docker avoids all of it.** Each database runs in a container:

- Try a system, then delete it: nothing left behind on your machine
- Run several at once without them fighting over ports or config
- The same setup runs identically on someone else's machine

It also pays off well beyond this course (it's how projects get deployed) so it was going to
be taught in the back-end subject anyway. It's simply needed here first.

**Install Docker Desktop:**
```powershell
winget install Docker.DockerDesktop
```

On Linux you install the Docker engine directly rather than Docker Desktop.

> ⚠️ Docker Desktop must actually be **running**, not just installed, before any `docker`
> command works.
