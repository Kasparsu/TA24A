## 🗂️ Topics Covered

### 1. 🐳 Why Docker, for a Database Course

You could install MariaDB directly and be done in a few commands. Docker is worth the detour
anyway, because of what it buys you:

- **Run anything on anything.** Any stack, any system, on top of Docker.
- **Deployment gets boring.** Install Docker on the server, pull the project, tell it to start.
  It fetches every dependency itself: no installing tools one by one on the server.
- **No lock-in to a host.** If your VPS provider puts prices up, you don't have to remember
  what an old project needed. Pull it down on the new machine, start it, done.
- **Container hosting exists.** Many providers now take a container config rather than giving
  you a Linux box at all.

> 💡 The same argument as self-hosting generally: what's open and portable stays yours. Anything
> paid usually has a self-hostable equivalent.

**Prerequisite:** Docker Desktop must be installed and *running* on Windows, or none of the
commands work.

### 2. 📄 `docker-compose.yml`: the First Service

Rather than typing long `docker run` commands, the setup is described in a file:

```yaml
services:
  web:
    image: httpd
    ports:
      - 8000:80
    volumes:
      - ./html:/usr/local/apache2/htdocs
```

| Key | Meaning |
|---|---|
| `services:` | Each entry is one container |
| `web:` | A name you choose |
| `image: httpd` | Use the official Apache image from Docker Hub |
| `ports: - 8000:80` | **host:container**: port 80 inside shows up as `localhost:8000` outside |
| `volumes: - ./html:/…/htdocs` | **host:container**: the local `html/` folder *is* the server's web root |

The volume is the important idea: the container is disposable, but your files live on your
machine. Edit `html/index.html`, refresh the browser, and the change is there: no rebuild.

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Document</title>
</head>
<body>
    Hello TA25A!
</body>
</html>
```

### 3. 🏗️ Building Your Own Image

Using a stock image is fine until you need something that isn't in it. Then you build on top:

```dockerfile
FROM httpd

RUN apt update

RUN apt install -y vim nano
```

| Instruction | Meaning |
|---|---|
| `FROM httpd` | Start from the official Apache image |
| `RUN …` | Run this command **while building the image** |
| `-y` | Answer "yes" automatically: nobody is there to confirm |

And point compose at it instead of the ready-made image:

```yaml
services:
  web:
    build:
      context: .
      dockerfile: dockerfile
    ports:
      - 8000:80
    volumes:
      - ./html:/usr/local/apache2/htdocs
```

`context: .` is the folder the build runs in; `dockerfile:` names the file.

> ⚠️ `RUN` happens at **build** time, not every start. Change the dockerfile and you must
> rebuild for it to take effect.

### 4. 🗄️ MariaDB and Adminer

The actual point of the course: a database, plus a browser UI for it:

```yaml
  db:
    image: mariadb
    restart: always
    environment:
      MARIADB_ROOT_PASSWORD: example
    volumes:
      - ta24alearndbdata:/var/lib/mysql

  adminer:
    image: adminer
    restart: always
    ports:
      - 8080:8080

volumes:
  ta24alearndbdata:
```

**What each part does:**

- **`environment:`**: configuration passed into the container. The MariaDB image reads
  `MARIADB_ROOT_PASSWORD` on first start and sets up the root account. Which settings exist is
  documented on the image's Docker Hub page: **always read it before using an image**.
- **`restart: always`**: bring it back up if it crashes or the machine reboots.
- **`ta24alearndbdata:/var/lib/mysql`**: a **named volume**, not a folder mapping. Docker
  manages the storage; you just give it a name. `/var/lib/mysql` is where MariaDB keeps its
  data.
- **`volumes:` at the bottom**: named volumes must be declared here as well as used above.

**Why the database gets a named volume instead of a bind mount:** you don't want to browse or
edit raw database files, you just need them to **survive the container being destroyed**.
Without it, `docker compose down` throws your data away.

**Adminer** is a single-file database admin UI. No `environment` needed: it asks for the
server, user and password in the browser at `localhost:8080`. The server name is `db`:
**containers reach each other by service name**, on a network compose creates for them.

## ✅ Takeaways

1. **Docker makes a project portable**: the server only needs Docker, not your toolchain.
2. **`ports:` and `volumes:` are `host:container`.** Getting them the wrong way round is the
   classic first mistake.
3. **A bind mount (`./html:/…`) is for files you edit**; a **named volume** is for data you
   only need to persist.
4. **`FROM` + `RUN`** builds a custom image; `RUN` executes at build time.
5. **Read the image's Docker Hub page** to learn which environment variables it accepts.
6. **Containers find each other by service name**: Adminer connects to `db`.
