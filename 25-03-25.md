## 🗂️ Topics Covered

### 1. 🌐 REST APIs & the Rick and Morty API

The session opened with a discussion of runtime errors vs compile-time errors — the kind of bugs that only appear when the code is actually running (e.g. trying to read data that doesn't exist yet). This set the stage for working with external APIs where you never quite know what you'll get back.

The class used the **Rick and Morty API** as a practical data source:
- The API returns paginated results — not all characters at once, just 20 per page
- The info object in the response contains: total count, total pages, `next` page URL, and `prev` page URL
- `prev` is `null` on the first page; `next` is `null` on the last page — useful for disabling pagination buttons

### 2. 🃏 Bulma CSS — Cards & Columns

The session used **Bulma** as the CSS framework to style the character cards. Key concepts covered:

**Cards:**
- Bulma's `card` component provides a ready-made layout with image, content, and footer sections
- Character images and names were mapped into card components

**Columns & Layout:**
- `class="columns"` creates a flex row that divides the space equally
- `class="column"` on each child takes an equal share — but only splits up to **12 columns** max
- Column sizes can be specified with classes like `is-3` (takes 3/12 = quarter of the row), `is-half`, `is-one-quarter`, `is-one-third` etc.
- **`is-multiline`** on the `columns` wrapper is the key to wrapping cards to the next row automatically when the row fills up — without it, cards just squish together

### 3. 🖼️ Vue 3 — Components, Props & Data Binding

The main coding work was done in **Vue 3** using the Composition API (`<script setup>`):

**Component structure:**
- A `CharacterCard` component was created to display each character
- The card component receives a `character` object as a **prop** from the parent
- Data (name, image) is bound dynamically using `:src="character.image"` and `{{ character.name }}`

**`v-for` to render lists:**
- Characters fetched from the API were iterated with `v-for="character in characters"` to render one card per character

**`onMounted` + async fetch:**
- Data is fetched when the component loads using `onMounted(async () => { ... })`
- `axios` was used to make the API call and store the result in a reactive variable
- The `info` object (containing pagination URLs) was stored separately from the results array

### 4. ⏭️ Pagination

The second half of the session focused on building working **Previous / Next pagination**:

- Two buttons were added: `Previous` and `Next`
- Each button calls an async function that fetches the new page using the `prev`/`next` URL from the API's `info` object
- **Disabling buttons** when there's no more pages: the `:disabled` attribute was bound to whether `info.prev` or `info.next` is `null`
  - Syntax: `:disabled="!info.next"` — disables the Next button on the last page
  - `:disabled="!info.prev"` — disables the Previous button on the first page
- A known issue was noted: rapidly clicking the buttons can fire multiple requests — the instructor mentioned this could be handled with debouncing in a future session
